> Spec (binding): `docs/superpowers/specs/2026-10-04-zippy-z5-order-note-and-followups-design.md`. Execute with `superpowers:subagent-driven-development`. Follow the Z4a/Z4b patterns in `lib/zippy/actions.ts`, `tools.ts`, `prompt.ts`, `validate.ts`, `action-types.ts`, `action-exec.ts`, `client-cart.ts`, `components/zippy/ActionCards.tsx`, `ZippyWidget.tsx`, `mobile/components/ZippyActionCards.tsx`, `ZippyFab.tsx`.

**Global constraints:** shared client files (`lib/zippy/action-types.ts`, `action-exec.ts`, `client-cart.ts`, `lib/cart-line.ts`, `stream-events.ts`) have byte-identical copies in `mobile/lib/` guarded by `tests/zippy-parity.test.mjs`; node-testable modules cannot value-import siblings (no `.ts` extensions allowed by tsconfig; inject helpers via `deps`); `tools.ts`, `agent.ts` and the route are server-only and untestable by node, so put logic in pure helpers; money is integer paise; no package installs; never stage `tsconfig.json`, `.superpowers` or `md_version`; commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; run `node --test tests/*.test.mjs`, `npx tsc --noEmit` and `cd mobile && npx tsc --noEmit` before every commit. Do not run `next build`, servers, or the model; do not touch the database. Lessons: re-read every prompt rule when adding a capability (a rule for one feature silently blocks the next); generic helpers must not leak kind-specific text (for example a 'tap Confirm' status string); parallel tool calls need a re-check after any await; live defects keep appearing in the handoff between components, so check every tool-to-card and card-to-client handoff.
